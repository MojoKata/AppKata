# R17.14. Uninstalling

R17.14. **Uninstalling** a sandboxed app offers to remove its private home
(`~/.local/share/appkata/sandboxes/<app>`), like any app data (R4.7); so does uninstalling an app
switched Off that still has one (review 2's nit: its home stayed behind, orphaned). A kept home remains that app's
alone (R17.6). What the app was handed through the document portal (R17.6.2) is taken back when it
is uninstalled, and when it leaves Standard for Strict or Off: the portal keeps a file or folder
handed over, under the app's id, for the login session, and an id an uninstall frees goes to the
next app of that name (R17.6), which found them in its own view, to read and to write (CR1.5-25).
AppKata asks the session's document portal, from the host side, to revoke each one for that id:
only for an app its file-argument helper handed something, and without starting a portal where
none runs; where the portal can't be asked the uninstall goes on, AppKata's log says so, and it
asks again before an app is next given a launcher under that id.
