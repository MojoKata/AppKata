# R17.12. Self-update

R17.12. **Self-update.** An app that updates itself (R4.10) can't while it runs sandboxed: its install
folder is read-only, and for an AppImage the `.AppImage` file too. So while it runs sandboxed —
whenever it has a launcher, R17.4 — AppKata updates it as if it didn't update itself (R4.10.5): the
Update button, Update all, the minimum age and pinning apply, and its next update moves it to
version folders, with the old fixed-name file kept as the previous version. App Detail says "It
would update itself, but it runs sandboxed and can't change its own files, so AppKata updates it",
and the install dialog's "This app updates itself" hint says the same. Its own updater simply fails
(how gracefully is each app's). When its sandbox is turned Off, it updates itself again, and
AppKata moves it back to the fixed-name layout of R4.10.2: its current version is renamed to the
fixed name, and its kept versions are removed (R4.10.5). (Review 2, F3: an
earlier draft named a "Disable the app's own updater" option, which R4.10.3–R4.10.4 rule out and
which was never built; nobody updated a sandboxed self-updating app.)
