# R17.18. Deferred to later releases

R17.18. **Deferred to later releases** (not v1): the **Wayland security-context** protocol (closes the
wlroots leak and KDE's clipboard leak, R17.9; sway since wlroots 0.17 and kwin 6 advertise it, shown in
the `wayland` and `kwin6` harnesses — the next release's first item); the **Landlock** layer as defense-in-depth inside bwrap (execute-deny, per-port
TCP); **personal templates** and **reviewer-defined/shared templates** (R17.3.4); **config import** on
enable-later (R17.13); a **fuller seccomp filter** beyond the terminal-injection one of R17.4
(Flatpak's: `ptrace` of other sandboxes, `perf_event_open`, unusual socket families); **squashfuse**
mounting instead of extraction (R17.7);
proprietary-**NVIDIA** device nodes; **enforcing play-only sound** (R17.8); a **capability-stripping AppArmor profile** for bwrap's children
on 24.04 (R17.10.1); a **spawner for Chromium's and Electron's own sandbox** on Ubuntu 25.04 and later
(R17.10.2: as Flatpak's zypak does, a host-side helper per launch that starts each sandboxed Chromium
child in its own, tighter bwrap, so the app's inner sandbox comes back instead of `--no-sandbox`); a
network of an app's own (**user-mode networking**, `pasta` or `slirp4netns`), which keeps the host's
abstract sockets out for every session (R17.9; review 3, R3-8); a machine-id of each app's own,
with `/sys` narrowed to what GPU drivers need, once real GPUs show that safe (R17.17; review 3, R3-7);
a filtered **AT-SPI proxy**, as Flatpak runs, so screen readers reach sandboxed apps
(R17.17; review 2, F15); a file still to be made handed
over as a name in its folder (the document portal's `AddNamed`, R17.6.2; review 3, R3-16); and
**App categories** in the Catalog (a separate feature, not
sandboxing). The real-hardware validation still owed is the checklist in `local-proxy-test-plan.md`,
run by `scripts/sandbox/field-test.sh` against a probe app AppKata itself installs, in a throwaway
home.
