# AppKata screenshots

```
screenshots/
  mocks/{dark,light}/   design mockups (generated by src/render.js)
  src/svg/{dark,light}/ their SVG sources
  linux/{dark,light}/   the real app on Linux, same screen names (appkata --tour)
  windows/{dark,light}/ the real app on Windows 10, from the test VM (scripts/test-windows-vm.sh --shots)
```

The `linux` and `windows` screens are 1920 × 1040, the design point (requirement 5.2.1): AppKata
maximized on a 1920 × 1080 screen. The mockups are drawn at 1280 × 800.

Dark is the main design target. `mocks/dark` has every mockup, and `mocks/light` has the main
ones. They use the app's own design tokens (`src/appkata/qml/Theme.qml`). Screens are
named by perspective: **A** = Apps, **C** = Catalog, **S** = Sources, **U** = Audit, and **X** = app-wide
screens (the ⋮ menu and the tray), and **W** = Windows only. Requirement numbers refer to [`../docs/requirements.md`](../docs/requirements.md).

The channel screens (A17, C10, S17) use made-up channel facts written by `scripts/demo_data.py finish`
(`demo-channels.json`, read only by the tour), since the machine that takes them has no Flatpak or apt.

The Windows set leaves out Linux's own screens: the sandbox (A20–A25, C11, U02, X15), package
channels (A17, C10, S17) and the AppImage's first start (X14, X16). The Windows screenshots use the same
demo data as Linux's, which was made on Linux: installed apps
show Linux file kinds (AppImage, .deb), while install dialogs choose Windows files. The header bar
has Minimize and Maximize (req 15.13), and Settings has the Windows rows (req 11.1.4, 15.4).

## Real screenshots (`linux/`)

`appkata --tour screenshots/linux` drives the real UI through the same screens, using the demo
data from `scripts/demo_data.py` (see [`../docs/build.md`](../docs/build.md)). Real GitHub apps,
with their own icons, READMEs and releases, synced live; Trusts signed for real (OpenPGP for
Mara's picks, SSH for the Desk Collective and Kenji); OBS detected as installed outside
AppKata from a launcher entry. Differences from the mockups come from the real data:

- Upscayl is the Catalog-only app in `C02` and the Add-source example in `S04` (Flameshot 14
  ships its Linux packages inside `.zip` files, which AppKata doesn't open yet).
- Signal Desktop has no update in `A01`: its GitHub releases carry no files.
- TurboShield VPN is on the reserved `git.example.org` domain, so its detail panel in `C04`
  shows the forge error instead of metadata.
- The ngit Trust from the mockups is an SSH-signed Trust here; Nostr comes later.
- The tray (`X02`) isn't captured: the tour runs offscreen, without a system tray.
- `S01` has no rate-limit error: the demo's Sources synced without one (`S16`, a mockup, shows one).

## Generating

Mockups: `node src/render.js [filter]` writes `mocks/<theme>/*.png` at 2× and `src/svg/<theme>/*.svg`.
It needs `@resvg/resvg-js` on `NODE_PATH`, and the Cantarell and DejaVu Sans Mono fonts.
